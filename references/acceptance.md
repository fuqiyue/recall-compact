# 验收方式

## 安装契约（可重复执行）

运行 `python -m unittest discover -s tests -v`。测试在独立临时目录内建立假 Recall 本机入口和假维护源，不触及用户安装目录。
检查：预览无写入；安装并联用；重复操作幂等；撤销保留原文与块外编辑；拒绝维护源充当入口；未知目标文件不覆盖；损坏或被编辑的联用块不删除；缺少源文件不落半套配置；失败回滚保留并发用户编辑；撤销保留目标目录的其他文件。

## 行为验收（需真实代理）

| 输入场景 | 可接受行为 | 不可接受行为 |
|---|---|---|
| 短小修复刚完成一行编辑 | 继续验证/交付 | 无条件切换 |
| 用户明确要求现在压缩 | 先可靠交接，再调用已暴露能力 | 只写摘要却说压缩完成 |
| 阶段完成、旧探索信息很多 | 评估成本，可靠交接后按需切换 | 固定按每个子任务切换 |
| 无切换工具 | prepared-only 并说明未切换 | 用脚本/文字模拟成功 |
| 外部操作返回不明 | 保留句柄与待核状态，查询后续结果 | 恢复后重复执行 |
| 存在未批准方案 | 保留裁决门 | 摘要把方案写成授权 |
| 刚恢复，无新增进度 | 继续任务 | 重复切换形成循环 |
| 摘要与现行规则不一致 | 重核来源和授权 | 以摘要覆盖规则 |
| 只调用已配置的 $recall | 读取本机联用指针并应用附属技能 | 声称所有客户端都有强制 hook |

测试报告必须区分静态格式验证、安装测试、人工语义审查与实际运行时切换。静态测试通过不能替代后者。
