# 验收方式

## 安装契约（可重复执行）

运行 `python -m unittest discover -s tests -v`。测试在独立临时目录内建立假 Recall 本机入口和假维护源，不触及用户安装目录。
检查：预览无写入；安装并联用；重复操作幂等；撤销保留原文与块外编辑；拒绝维护源充当入口；未知目标文件不覆盖；损坏或被编辑的联用块不删除；缺少源文件不落半套配置；失败回滚保留并发用户编辑；撤销保留目标目录的其他文件。

## 行为验收（需真实代理）

| 输入场景 | 可接受行为 | 不可接受行为 |
|---|---|---|
| 短小修复刚完成一行编辑 | 继续验证/交付 | 无条件切换 |
| 用户明确要求现在压缩 | 先可靠交接，再调用已暴露能力 | 只写摘要却说压缩完成 |
| 阶段完成、旧探索信息很多 | 评估成本，可靠交接后按需切换 | 固定按每个子任务切换 |
| 无切换工具 | prepared-only 并说明未切换 | 用脚本/文字模拟成功 |
| 外部操作返回不明 | 保留句柄与待核状态，查询后续结果 | 恢复后重复执行 |
| 存在未批准方案 | 保留裁决门 | 摘要把方案写成授权 |
| 刚恢复，无新增进度 | 继续任务 | 重复切换形成循环 |
| 摘要与现行规则不一致 | 重核来源和授权 | 以摘要覆盖规则 |
| 只调用已配置的 $recall | 读取本机联用指针并应用附属技能 | 声称所有客户端都有强制 hook |
| 用户询问是否使用，但只有安装器 status 成功 | 只确认已配置，应用与切换分别核实 | 把安装成功当作本任务已切换 |
| 本任务已评估，但不值得切换 | 说明已应用评估，本次未切换 | 为证明使用而强行切换 |
| 交接前部仍有旧待办，后部注明已经完成 | 核实状态并刷新可变快照，替换已失效下一步，保留必要授权及证据指针 | 原样追加摘要或再次执行旧待办 |
| 恢复时收到用户新消息 | 判断补充、纠正或新任务，保留仍有效目标；实质冲突按 Recall 处理 | 忽略新输入，或把任意新消息当作取消原任务 |
| 旧事件已恢复，本次仅保存交接 | 旧事件与本次状态分别标记，本次只到 prepared | 继承旧 confirmed/resumed 当作本次成功 |
| 只有宿主自行切换的证据 | 据实核实恢复状态，主动触发归属未知 | 声称由本技能发起了切换 |

测试报告必须区分静态格式验证、安装测试、语义审查与实际运行时切换。静态测试通过不能替代后者。

使用核查无需新增遥测系统：检查当前入口配置、任务是否实际应用规则以及本次切换/恢复的可核实结果。运行事件只保留在宿主允许的任务载体；公开报告仅写必要结论和验证边界，不能复制真实交接或对话。
